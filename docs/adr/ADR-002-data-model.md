# ADR-002: Data model conventions and passport encryption

- Status: accepted
- Date: 2026-10-10

## Context

The first migration fixes choices that are expensive to change once data exists: key types, how business rules are enforced, how translated text is stored, and how the passport number (the most sensitive field of the platform) is protected.

## Decision

| Topic                                            | Choice                                                                                 | Reason                                                                                                                |
| ------------------------------------------------ | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Primary keys                                     | UUID from `gen_random_uuid()`                                                          | Ids appear in URLs and must not be guessable or reveal volumes; generated by the database so raw SQL inserts work too |
| Translated text                                  | One JSON column `{en, fr, ar}` per field                                               | Three fixed languages; avoids a translation table and joins for short labels                                          |
| Destinations                                     | Table with a stable `code`                                                             | SPEC: new countries can be added without a deployment                                                                 |
| Job languages, licence categories, alert filters | PostgreSQL arrays                                                                      | Short lists that are filtered, never edited row by row                                                                |
| Simple invariants                                | `CHECK` constraints written by hand in the migration                                   | They hold whatever code writes to the database (API, seed, scripts)                                                   |
| Full-text search                                 | Generated `tsvector` column with a GIN index, `simple` configuration                   | No trigger and no application code to keep it up to date; `simple` because offers are multilingual                    |
| Email uniqueness                                 | Lower-cased by the API, enforced by a `CHECK`                                          | Avoids the `citext` extension, which has to be allow-listed on Azure Flexible Server                                  |
| Passport number                                  | AES-256-GCM in the API, plus a masked column                                           | Protects against database dumps, backups and SQL read access; lists never need the key                                |
| Encryption key                                   | One key from the environment, Key Vault in Azure; payloads carry a `v1` version prefix | Simplest scheme that still allows rotation                                                                            |
| Tokens                                           | SHA-256 hash only                                                                      | A leaked table cannot be replayed                                                                                     |
| Seed                                             | Create when missing, never update                                                      | Running it again cannot reset an admin password or a setting changed in the back office                               |

## Consequences

- Prisma does not know the generated column. It is declared `Unsupported("tsvector")?` with a `dbgenerated` default that repeats the expression exactly as PostgreSQL stores it; without this, `prisma migrate dev` reports drift. Changing the expression needs a hand-written migration.
- `CHECK` constraints are invisible in `schema.prisma`. They are listed in `docs/ARCHITECTURE.md`, which must be updated with any migration that adds one.
- Passport numbers cannot be searched or sorted in SQL. A keyed hash column can be added if duplicate detection is required.
- Losing `PASSPORT_ENCRYPTION_KEY` loses the passport numbers. The key needs a backup and, later, a rotation script.
- `simple` search does not stem words. If search quality matters more than multilingual support, add per-language columns later.
- Enum values exist twice (Prisma and `packages/shared`). A test compares them.
- `home_slides.cta_label` is translated JSON, not plain text as first listed, because it is shown to visitors in three languages.
- Candidate profile fields other than the names are nullable, so an account can exist before the profile is complete. The API must check completeness when a candidate applies.
