# ADR-013: Azure infrastructure on a student subscription

Date: 2026-10-15. Status: accepted.

## Context

IconBridge Jobs runs on an Azure for Students subscription: a 100 USD credit, a spending limit, a policy that allows five regions, one Container Apps environment per region, and twelve months of free services (one PostgreSQL B1ms server with 32 GB, 5 GB of Blob storage, and, according to the offer, one Standard container registry). The infrastructure must stay inside that credit for the duration of the internship while protecting candidates' identity documents.

## Decisions

1. **Terraform, remote state in Azure Storage with Entra ID.** A bootstrap configuration with local state creates `rg-iconbridge-tfstate` and a storage account with versioning, soft delete, TLS 1.2, no public blobs and **shared key access off**; backends use `use_azuread_auth`. Modules per concern; `envs/prod` composes them.
2. **Italy North**, the first region allowed by the policy that offers both Container Apps and an unrestricted PostgreSQL B1ms (docs/00-environment.md).
3. **Public endpoints with identity and TLS, not VNet integration.** A VNet-integrated Container Apps environment, private endpoints for PostgreSQL, Key Vault and Storage, and private DNS zones would be more secure: the database and the vault would not be reachable from the internet at all. But each private endpoint costs about 7 USD a month (three needed: about 22 USD, plus private DNS zones), which alone exceeds the 15 USD monthly budget; the VNet-integrated environment also needs a dedicated subnet and makes the setup harder to reason about for one developer. Instead:
   - PostgreSQL accepts Azure-hosted clients (rule `0.0.0.0`) and the administrator's IP, requires TLS 1.2, and its password is random and lives in Key Vault. The risk left: any Azure tenant can attempt a connection; the password is the barrier. Revisit when the budget allows a VNet.
   - Key Vault and Storage are reachable publicly but only with Entra ID tokens (RBAC, no access policies, no account keys).
4. **One user-assigned managed identity** for the apps and jobs: AcrPull, Key Vault Secrets User, Storage Blob Data Contributor and Storage Blob Delegator. The API signs download links with user-delegation SAS, so the storage account needs no key: **shared key access is disabled**.
5. **Secrets generated by Terraform** (database password, JWT secret, passport encryption key, revalidation secret, first super admin) are written to Key Vault and referenced by the Container Apps through the identity; their values never appear in the app configuration. Secrets only the owner has (Turnstile; email needs none since [ADR-014](ADR-014-email-azure-communication-services.md)) are created with a placeholder and `ignore_changes`, then set by hand. The values are also in the Terraform state, which is why the state storage has no key and is reachable only by the deployer.
6. **Registry chosen by a variable.** `acr` (Standard, admin user off, pull by identity) while it is free; `ghcr` (GitHub Container Registry, free) afterwards, with a read-only token in Key Vault.
7. **Costs capped by construction**: PostgreSQL exactly B1ms/32 GB/7-day LRS backups (never larger, never a second server); Log Analytics capped at 0.15 GB a day (below the 5 GB monthly free volume); Container Apps scale to zero (min 0, max 2; API 0.5 vCPU/1 GiB, web 0.25 vCPU/0.5 GiB); a resource-group budget of 15 USD with alerts at 50, 80 and 100 %.
8. **One Container Apps environment, created by `envs/prod`** (in `ConsumptionOnly` mode, set explicitly since [ADR-015](ADR-015-container-apps-environment-mode.md)) and read by a future staging, which also uses a second database on the same server.
9. **Internal API.** Only the web app has an external ingress; it forwards `/api/v1/*` to the API's internal address, so session cookies stay first-party. The API's health is visible through the web app at `/api/health/ready`; the web app's own probes use `/api/health/live`, which does not call the API, so probes never keep the API awake.
10. **Images outside Terraform.** The first apply uses Microsoft's public quickstart images; the pipeline sets the real image, and Terraform ignores the `image` attribute. With `min_replicas = 0` no placeholder replica runs before the first request.
11. **Data protected from Terraform itself**: `prevent_destroy` on the database server, the database, the application storage and its containers, and the state storage. Key Vault relies on purge protection (7 days) instead.
12. **Static checks**: `terraform fmt`, `validate`, tflint with the azurerm ruleset, checkov. Each skipped checkov rule is listed with its reason in `infra/terraform/.checkov.yaml`; most are the private-network and Premium-tier features declined in point 3 and 7.

## Consequences

- Expected cost while the free services last: under 1 USD a month. Without them: about 42 USD a month (registry 20, database 21), which the budget alerts would show within days. The registry is then moved to ghcr.
- The database is exposed to connection attempts from Azure; its security rests on the password and TLS.
- Container Apps fetch Key Vault secrets when a revision starts: after changing a secret by hand, restart the revision.
- A cold start (API and web scaled to zero) takes several seconds on the first request.
