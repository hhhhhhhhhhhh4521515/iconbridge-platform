# Production audit, November 2026

Audit: 2 November 2026, site <https://iconbridgerecruitment.com>, version `9ddf425`. Status updated on 12 November 2026 (version `064d551`). Final audit on 13 November 2026 (version `e4f641c`), [below](#final-audit-13-november-2026). Scope: functional, security, Azure, email, legal, quality, operations.

**Method.** Read-only checks only:

- the public site and the API were called anonymously;
- the candidate area was opened with the dedicated test account only (no form sent, nothing created or deleted); the super admin was never used;
- Azure was read with `show` and `list` commands;
- one backup was restored into a temporary local database, counted, then dropped;
- no load test.

The back office, which the test account cannot open, was checked through the browser test suite and its access control through the live API.

This document is public, like the repository. It names no address, account, subscription id or secret, and it describes open findings only as far as needed to follow their fix.

## Findings

### H1 — Database endpoint and password login (High)

**Found.** The PostgreSQL server had public network access, a firewall rule for Azure services and a stale administrator address, and accepted the administrator's password only.

**Part 1, fixed.**

- 8 November: the stale address rule was removed.
- 11 November: the API, the tasks, migration and backup jobs sign in with Microsoft Entra tokens of their managed identity (ADR-026).
- 12 November: password authentication is off on the server. A connection now needs a token issued by the platform's tenant to its identity.

**Part 2, planned.** Private networking: a Container Apps environment in a virtual network and a private endpoint for PostgreSQL, which removes the public endpoint. It means recreating the environment, so it is a change of its own through `infra.yml`, with the owner's approval.

### H2 — Emails with a link (High), fixed

Reset and verification emails are limited per address, as well as per client, with the same answer whatever the address. Turnstile protects the forms that send them. Tests cover the limit and the unchanged answer.

### M1 — Oversized request bodies (Medium), fixed

A body that is too large or of the wrong type answers 413 or 400, never 500, so it no longer counts towards the server-error alert. Covered by an e2e test.

### M2 — Bounced emails (Medium), fixed

Delivery reports reach the API through Event Grid with a key, and an address that bounces is no longer written to (live since 11 November).

### M3 — DMARC without reports (Medium), planned

In steps, never faster than the reports allow:

1. add aggregate reports and watch them for 2 to 4 weeks;
2. `p=quarantine` for part of the mail, then all of it;
3. `p=reject`.

### M4 — Privacy policy (Medium), fixed

The policy was rewritten from what the code does, in the three languages: what is collected and why, legal bases, providers and where they are, retention (including the 24-month deletion), rights and contact, date of the last version. A lawyer's review remains the owner's action.

### M5 — Log Analytics daily cap (Medium), fixed

On 7 November, the web app's internal rendering spans were left out. As traffic grew, the workspace reached its cap every day from 4 to 11 November, and the log alerts had no data until the daily reset.

On 12 November (ADR-028), the remaining noise was cut, and the cap stays where it is:

- no spans for opening database connections;
- no performance counters;
- no log line for successful requests;
- traces sampled at 50 % by trace id, while the metrics behind the alerts still count every request.

### M6 — Home page on a phone (Medium), fixed

The first hero picture is loaded with priority and served without waiting for the image optimiser.

### M7 — Spending and credit (Medium), owner's action

The subscription's offer does not report prices through the API. The owner follows the spending and the remaining credit in the portal.

### M8 — Key Vault and storage networks (Medium), planned

Both already require Entra identities and roles, and storage refuses account keys. Private endpoints and a closed default network rule come with H1 part 2. The public media container stays readable, because it holds the site's images.

### M9 — Malware scanning of uploads (Medium), planned

Files are typed from their content, images are re-encoded and documents are served from the storage origin. Microsoft Defender for Storage malware scanning has a cost per GB and per account, so it is a decision for the owner.

### M10 — Required checks (Medium), fixed

All 11 checks that run on a pull request are required before merging.

### M11 — Alerts on failed scheduled runs (Medium), fixed

**Found on 12 November**:

- the tasks alert fired twice while every run succeeded: after the daily cap of Log Analytics reset, the console lines of the job were lost for two hours;
- its "failed run" check, and the backup alert, matched job events by name, and Container Apps writes those events under a shortened name, so a failed run would never have fired either alert.

**Fixed**: failed runs come from the platform metric of each job, which does not depend on Log Analytics. "Not running" reads the job's container starts and stays quiet while the daily cap holds logs back. Replayed over two days of logs: no false alert.

## Final audit (13 November 2026)

**Scope:**

- the public site, the candidate area, the back office and the new partner spaces (ADR-027);
- the API, the Azure configuration and CI/CD;
- against the OWASP Top 10: access control and IDOR, authentication and sessions, rate limits, file uploads, headers and CSP, secrets, dependencies.

**Method**: the same read-only rules as above.

- The test candidate account only; no real data created; everything named `E2E …` removed.
- Azure and GitHub read with `show` and `list`.
- Access control proved by the test suites (the IDOR suite runs every partner route for members, seven kinds of outsider and visitors).
